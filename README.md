# 本草知问 · 中药知识库问答

最近归档快照：**V2.0（2026-11-19）**，对应 [GitHub V2.0 分支](https://github.com/17346733172/zhongcao/tree/V2.0)。本次在原快照基础上汇总 2026-11-16 至 2026-11-18 的更新：五模块 MCP 与 AI Agent 语义调度、设备默认用时保存、测试任务与历史批次、主页面导航和滚动、Agent 回答格式，以及 Windows 登录自启。具体功能与能力边界见下文。

面向整理中药资料并据此提问的用户。按用户最新 DeepSeek 排版参考采用浅灰侧栏、白色主区和统一无衬线字体，提供 **Python / FastAPI 后端、真实登录、角色权限和 DeepSeek 资料问答**。

## 当前功能

- 主页面统一纵向滚动，回答区域不再出现内外两层滚动条；标题和输入区保持可操作，运行总览与AI Agent切换保留阅读位置。

- 聊天回答按最新参考采用 Agent 信息栏、任务标签、北京时间、实际工具调用记录、白底正文及条件图表。运行总览可展示真实批次状态分布，测试方案可展示当前默认分钟数；表格数据可展开核对。模型工具选择返回实际 Token 用量时显示输入/输出计数，并明确口径；缺少字段时不显示虚构记录或图表。正文保持常规字重，引用和复制继续可用。

- 聊天回答统一采用常规字重：回答标题、小节标题、正文强调及表头均不加粗，保留原有字号与分节结构。

- AI Agent 统一按问题语义选择五个MCP工具，取消“未命中关键词就查原文”的默认分流。进度、耗时、卡点、设备与报警查询来自仿真平台，只有药材/方剂知识问题才查资料；模型或工具失败明确报错，不回退成资料未命中。可问“帮我看看最近几个方子用时，都卡在哪一步”，读取最近批次的当前工序、等待原因和实际处理分钟数；配置时长单列，排队/暂停时长缺失时不推算。见 [MCP 工具说明](docs/MCP-TOOLS.md)。

- AI Agent 支持“帮我下3个测试任务”“下3个测试方子”“下三份测试处方”等明确创建指令；数量校验独立于模型选择，须为1–50的确定整数，生成后不自动启动。

- 五个模块已封装为标准 MCP 工具：中药基础资料、数据中心、运行总览、测试执行与测试方案。页面 AI Agent 通过 MCP 调用，并可用自然语言明确生成演示批次、启停仿真和修改设备默认分钟数；外部 Agent 通过 stdio 连接，使用现有账号鉴权。保留原文引用、真实读取时间、过期标记、版本校验与单次写入。更新依赖后重启后端；配置与能力边界见 [MCP 工具说明](docs/MCP-TOOLS.md)。此条替代此前聊天仅支持只读运行查询的范围；不控制物理设备。

- 运行总览已移除「全局仿真状态」右侧的「累计运行」标签与时长数字，保留平台状态、数据读取时间、指标及设备信息；此条替代下文运行总览展示累计时长的旧说明。

- 测试方案读取恢复修复：旧平台优先复用数据中心共享快照及原读取时间；连接失败只重试读取，不重复保存。页面读取失败或数据过期时每 15 秒自动重试，保留上次值，并合并连接错误与只读说明。手动重新读取会重新确认平台接口能力；修改接口未部署的限制仍保留。见[读取恢复验收](docs/DEVICE-DEFAULTS-RECOVERY-QA.md)。

- 「测试方案」可修改 13 类设备的当前默认每次用时，按分钟输入，范围 0.1–120，支持逐类真实保存、还原当前值、重新读取、输入校验及并发冲突反馈。药锅不设固定用时。**当前仿真服务器已于 2026-11-18 接通保存接口**；已有页面若仍显示只读提示，点击「重新读取」。保存影响后续创建的数据，已有批次时长保留，处方显式工艺参数优先。见[真实保存验收](docs/DEVICE-DEFAULTS-ENABLE-QA.md)和[接收端配套说明](integrations/README.md)。

- 「历史批次」按当前累计概览的同一仿真平台读取已完成批次及关联处方编号，展示状态、进度和追溯码，每页 20 批，可翻页、自动更新和手动刷新。标签数量来自累计概览，列表显示实际读取总数与时间，更新时刻不同造成的差异会说明；读取失败保留同页结果。此条替代下文历史批次仍为占位的说明；测试判定、报告与导出仍待接入。见[历史批次验收](docs/COMPLETED-BATCHES-QA.md)。

- 测试执行的「实时测试记录」与「测试记录」现展示状态严格为「进行中」的批次及关联处方编号，包含当前工序、进度和等待原因；「全部记录」切换到同一列表。共用数据中心快照自动更新和手动刷新，批次完成 / 暂停后移出，加载、空结果、过期和失败保留有明确提示。此条替代下文测试记录仍为空占位的说明；测试判定、报告与导出仍待接入。见[进行中批次记录验收](docs/RUNNING-BATCHES-RECORDS-QA.md)。

- 侧栏显示「中药基础资料」「数据中心」「运行总览」，以及测试、智能两组共四个入口；按用户要求暂时移除「设备与系统」分组和「设备配置」「系统设置」。登录后默认展示运行总览；「AI Agent」保留现有完整问答页，点击保留当前对话与草稿（[入口验收](docs/AI-AGENT-ENTRY-QA.md)）；「测试执行」与「测试方案」可操作，「Token 统计」仍待补充。侧栏「数据中心」下方的同级「运行总览」直接切换主区，展示已有平台状态、指标、批次和设备分类；数据中心只保留「概览 / 设备与异常 / 全部处方」三个标签，与主区共享快照读取和刷新。最新见[数据中心三标签验收](docs/DATA-CENTER-THREE-TABS-QA.md)和[主页面验收](docs/OPERATIONS-MAIN-PAGE-QA.md)；此前[快捷入口验收](docs/OPERATIONS-SHORTCUT-QA.md)和[入口迁移验收](docs/OPERATIONS-TAB-QA.md)保留为历史记录。

利用率 / 占用率问题也进入数据中心：读取设备累计利用率，区分读取时使用中台数占比，支持具体锅号与同主题追问。平台当前没有完整日工作时长记录，因此「今天锅的利用率」会明确说明当天统计暂不可准确计算，下面仅展示标明口径的累计 / 当前参考；设备表对应字段标为「累计利用率」。见[利用率问答验收](docs/DATA-CENTER-UTILIZATION-QA.md)。

## 处方检查 Agent

登录后点击输入框旁「处方检查」打开独立检查弹窗，三种角色均可使用；基础资料弹窗不再提供重复入口。支持 TXT、MD、DOCX、PDF、PNG、JPG、WEBP，每次一份处方，单文件 10 MB，PDF 最多 8 页；也可粘贴文字或手动录入。关闭整个弹窗后清除本次处方，聊天草稿保留。

后端使用 **LangGraph** 编排解析、人工核对、规则检查和报告。图片与扫描 PDF 改为现有 DeepSeek 配置的多模态解析，一次模型请求完成分类、文字转录和处方字段提取，不再运行本地 RapidOCR。TXT、MD、DOCX 和可读文本 PDF 继续读取文字，再识别意图并提取字段；非处方或多个处方版本会要求补充。用户逐项对照原图或原文核对药名、剂量、单位与每剂量口径后才能检查，修改后需再次确认。

处方识别与核对支持「枚」「片」，如大枣 3 枚、生姜 3 片，分别保留数字与单位。模型漏填时，仅从对应药物行的唯一、明确计数量恢复；范围、分数、多个数量仍留给人工核对，不按药名猜测、不换算克数。图片字段只做与模型转录的一致性校验，不等于独立核验原图，必须人工对照。已有缺失结果需重新识别，见[计数单位识别验收](docs/COUNT-UNIT-LABELS-QA.md)和[多模态解析验收](docs/MULTIMODAL-PRESCRIPTION-QA.md)。仿真上传也支持「枚」「片」，分别使用独立计数类型并保留原单位，见[枚单位上传验收](docs/ITEM-UNIT-QA.md)。

按用户已明确的要求，处方默认按「每一剂的量」检查。上传与核对页显示「本方剂量口径」：选择随提取请求、药物表格、后端检查和报告完整传递，新增药行继承当前口径；不再要求额外点击每剂量确认按钮。药量数字不变，仍须核对原文后勾选确认；可改为总量或逐味设置。

信息不完整时，3.1 结论下会直接列出本次需补充的具体项目，例如患者年龄、过敏史，或第几味药的剂量、单位、口径；已提供的字段不重复要求补充。点击「去补充信息」可保留已有数据并定位第一个缺失字段，补充后再次确认检查，已补齐项自动从清单移除；复制报告也包含该清单。仍可通过「修改数据后复查」调整其他数据。

从报告点击「修改数据后复查」或「去补充信息」时，系统定位首个缺失字段，并用红框标出本次仍需补充的输入项。补齐一个字段，红框立即恢复为常规边框。处方流程已移除 OCR 初始化、预热和直接依赖；旧 `OCR_WARMUP` / `OCR_BACKEND` 配置不再使用。当前图片解析需要配置支持视觉输入的 DeepSeek 模型，详见[多模态解析验收](docs/MULTIMODAL-PRESCRIPTION-QA.md)；[OCR 提速验证](docs/OCR-PERFORMANCE-QA.md)保留为历史记录。

报告按用户给出的五节审核意见格式输出：**3.1 审核结论、3.2 主要问题、3.3 毒性药材与煎法核查、3.4 其他核查、3.5 处理建议**。结论加粗，正文使用条目，处理建议使用编号及子项；去掉原来的计数、卡片、明细折叠与范围面板。内容按当前处方生成，复制为同样的 Markdown 分节正文；格式及验证见[分节报告验收](docs/PRESCRIPTION-REPORT-QA.md)。3.1 由系统直接给出「通过 / 不通过 / 待补充信息」及具体判断依据。已接入十八反、人参—五灵脂十九畏、采用参考剂量和特殊煎法；普通用药提醒不自动阻断通过。新增依据与示例验证见[系统判定验收](docs/PRESCRIPTION-DECISION-QA.md)。

检查基本信息缺失、非法数值、单位、重复饮片、有限十八反配伍、部分特殊煎法及本地资料参考剂量。报告附依据与复核提示，支持复制；「通过」只表示本次已确认数据在系统覆盖项目内通过辅助审核，不代表完整临床安全评估或实际调配授权。尚未接入完整现行药典数据库、全部十九畏 / 妊娠禁忌、西药相互作用及诊断适宜性审核。

处方不写入共享知识库，不持久化原文件或报告；关闭弹窗后需重新上传。图片、扫描 PDF 的页面图像会发送至配置的 DeepSeek 云端模型，图片中的身份信息不会自动遮盖，请上传前自行脱敏；提取的文字仍作基础标识遮盖。确认页明确标注「模型转录」，保留原始图片和 PDF 对照入口。复用后端 DeepSeek 密钥与模型配置；未配置时可手动录入并运行数据检查。详见[处方 Agent 说明与验收](docs/PRESCRIPTION-AGENT.md)。

检查结果页可点击「上传到仿真平台」，将总剂数和逐味药材明细录入煎药流程仿真平台。平台保存匿名处方并等待人工审核。上传支持 1–30 剂、克、毫克、枚或片及常规、先煎、后下、包煎；总量按剂数均分，工艺采用仿真平台默认值。枚数、片数按各自计数单位传递，例如大枣每剂 3 枚、5 剂合计 15 枚，生姜每剂 3 片、5 剂合计 15 片；不会将枚改写成片，也不将计数当成克数。平台审核时补充每剂实测克数后才能计算水量和创建批次；接收端须同步更新计数单位协议。校验失败时，提示内的「确认药材」可返回核对页并定位对应药物行，保留数据，修改后需重新勾选确认并检查，再上传。默认连接本机 `http://127.0.0.1:8080`，其他部署地址或 API Key 在本草后端配置。见[仿真上传配置](docs/DEVELOPMENT.md#仿真平台上传)。

片数协议与桌面 / 手机流程的验证结果见[片数计量验收](docs/COUNT-UNIT-QA.md)。

仿真平台的本机实例与服务器实例各自保存处方。连接服务器时，在 `backend/.env` 将 `DECOCTION_BASE_URL` 设置为实际服务入口；HTTP Basic 网关认证通过 `DECOCTION_HTTP_USERNAME` / `DECOCTION_HTTP_PASSWORD` 配置，修改后重启本草后端。

对接代码位于 `backend/app/integrations/decoction.py`，接口、字段对应、认证和排障见[两个项目的后端对接说明](docs/DECOCTION-INTEGRATION.md)。

上传遇到网络超时或连接中断时，后端最多尝试 3 次，每次沿用同一处方编号；页面最多等待 120 秒。仍未确认时保留报告，可再次点击上传。平台按编号防止重复录入。

## 页面排版

桌面采用可收起侧栏与白色聊天区。新会话显示居中的欢迎语和圆角多行输入框，发问后输入框移至底部。按 2026-11-16 最新要求移除右上角「知识库资料」按钮，将输入框旁的回形针替换为带图标的「处方检查」按钮，直接进入独立处方检查弹窗；原共享资料上传 / 管理面板及前端逻辑已删除。所有登录用户均可使用新按钮，不受资料加载状态影响。左侧入口改为「中药基础资料」，弹窗只保留文档阅读、章节定位与下载，移除处方检查标签；回答正文引用继续可用。回答、标题与正文统一无衬线字体，引用和 AI 补充标识保留。视觉参考与验收见 [设计规范](DESIGN.md) 和 [视觉验收](design-qa.md)；[原资料入口验收](docs/KNOWLEDGE-ENTRY-QA.md)为旧布局记录。

账号区、顶部标题、上传按钮与底部说明按最新字体参考统一使用本地 DM Sans 搭配系统中文字体；主标签桌面 18px、手机 16px，辅助文字 14px，均采用常规字重；侧栏分组标题为 13px。字体文件与开放许可位于 frontend/public/fonts，页面无需连接外部字体服务。侧栏改动验证见[侧栏验收](docs/SIDEBAR-MENU-QA.md)。

回答正文按用户提供的 DeepSeek 截图调整为 16px、1.75 行高，标题采用清晰的加粗层级，阅读列最大宽度 800px；来源小标签与标题同排。生成正文支持段落、加粗、列表、引用、代码和表格，原文在引用弹窗中保持原字面文本；窄屏表格可单独滚动，复制保留 Markdown 与来源标识。普通 AI 和知识库模式均向模型说明按需使用这些排版，不改变资料与 AI 补充的边界。对照与验证见 [视觉验收](design-qa.md)。

## 前后端分离

- `frontend/`：Next.js / React / TypeScript，负责登录、知识库和账号管理界面，独立安装依赖和启动。
- `backend/`：Python / FastAPI，负责认证、权限校验、账号和资料 API 及 SQLite，独立安装依赖和启动。
- 前后端通过 HTTP API 通信；本地由 Next.js 将 `/api/*` 同源代理到 FastAPI，业务逻辑和数据库访问集中在后端。前端通过服务端 `BACKEND_URL` 配置后端地址。

## 本地运行

环境：Python 3.11+、Node.js 20.9+、pnpm 11。

已完成首次安装后，推荐双击根目录 [启动本草.cmd](启动本草.cmd)：同时启动独立的前后端后台进程，等待登录页、后端健康接口和前端 API 代理全部就绪后显示访问地址。关闭启动窗口或开发工具不结束这些服务；未启用下述登录自启时，电脑重启后需重新运行。模型预热通常需要 1–3 分钟，启动期间重复点击会复用正在启动的进程。

日志位于 `tmp/local-servers/backend.log` 和 `frontend.log`（不提交）。可在项目根目录运行 `powershell.exe -NoProfile -File scripts/start-local.ps1 -Check` 检查当前连通性；失败时查看日志，不会显示虚假的启动成功。该入口适用于已安装依赖、配置管理员、模型与索引的 Windows 本机环境。

**重启后自动恢复：**在项目根目录运行 `powershell.exe -NoProfile -File scripts/set-autostart.ps1`，为当前 Windows 账号启用登录后静默启动，等待模型预热后访问原网址即可。它只添加当前用户的启动快捷方式，不需要管理员权限，不会自动打开浏览器。启动结果记录在 `tmp/local-servers/startup.log`。检查设置用同一命令加 `-Check`，关闭自启加 `-Disable`；关闭自启不停止当前服务。移动项目目录前先关闭，移动后重新启用。详细说明见[开发与验证](docs/DEVELOPMENT.md#环境与启动)。首次安装仍按以下步骤操作：

1. 双击根目录 **启动后端.cmd**。首次运行会建立独立虚拟环境、安装依赖，并提示设置管理员账号与密码（至少 10 位，输入时不显示）。保持终端开启。
2. 双击 **启动前端.cmd**，保持终端开启。
3. 打开 [登录页面](http://127.0.0.1:3000/login)，使用刚设置的账号登录。从左下角「账号管理」创建其他账号并分配角色。

两个脚本均支持 `--check` 检查运行环境。后端接口文档：[Swagger UI](http://127.0.0.1:8000/docs)。写接口需要 `X-CSRF-Protection: 1` 请求头；浏览器客户端已自动携带。

手动启动后端：

```powershell
cd D:\本草\backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.cli create-admin
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

另一终端启动前端：

```powershell
cd D:\本草\frontend
pnpm install --frozen-lockfile
pnpm dev
```

可将 backend/.env.example 复制为 backend/.env 修改数据库位置、允许来源及 Cookie 配置；启动时自动读取，已有系统环境变量优先。frontend/.env.example 可复制为 frontend/.env.local 修改服务端 `BACKEND_URL`，修改后须重启开发服务或重新构建。不要将密码和实际 .env 提交到 Git。

## 本地向量知识库 RAG

只使用今天接入的 Qwen3 + FAISS 向量 RAG，旧关键词检索入口已停用。新增查询向量缓存，以及按账号隔离、120 秒有效的已校验回答缓存；相同问题、上下文和检索原文未变时省去重复计算。提速说明见 [RAG 性能验收](docs/RAG-PERFORMANCE-QA.md)。

后端现在默认先加载并预热本地向量模型，再提供 API；终端出现 `Local vector RAG ready` 后即可使用。本机本次启动准备为 48 秒，期间无需重复启动。CPU 默认保留原始 BF16 权重，逐层以 FP32 计算，减少常驻内存；保持原模型、查询指令和现有索引。可用 `EMBEDDING_CPU_STORAGE=fp32` 对照；`RAG_WARMUP=false` 会恢复延迟初始化，首条提问需承担初始化耗时。

按用户参考项目组织为 `code/data`、`code/db`、`code/RAG` 和 `code/main.py`。指定的 69 页 PDF 已逐字校验后导出 Markdown，保留 7 张表格，原件与校验记录统一位于 `code/data`。知识库使用本地 Qwen3-Embedding-0.6B + FAISS；普通 AI 模式保持隔离。

首次使用先安装后端依赖，运行 `backend\.venv\Scripts\python.exe code/download.py --source modelscope`（或默认 Hugging Face），再运行 `backend\.venv\Scripts\python.exe code/main.py --rebuild`，完成后重启后端。模型和生成索引不提交到版本库；后续新增 Markdown 放进 `code/data`，共享上传文本继续参与检索。完整配置、终端问答、索引更新和兼容模式见 [RAG 说明](docs/RAG.md)，实际验证见 [RAG 验收](docs/RAG-QA.md)。

## 配置 DeepSeek

将 backend/.env.example 复制为 backend/.env，在本机填写 DEEPSEEK_API_KEY；不要在聊天或源码中发送密钥。默认 DEEPSEEK_BASE_URL=https://api.deepseek.com、DEEPSEEK_MODEL=deepseek-flash，均可由后端配置。保存后重启后端，刷新页面；发送默认检索原文并生成 AI 回答，无需选择按钮。未配置时显示配置提示，请求失败保留草稿。

密钥仅在后端读取。页面每次发送当前问题、知识库模式最近 5 轮摘要及最多 3 个检索片段；未命中的自然语言可能先单独进行语义整理，再重检资料（额外一次模型请求）。每轮摘要的问题最多 500 字符、回答最多 1000 字符；向量分块默认 500 字符、重叠 50，最多 3 段；保留 3000 字符的服务端片段上限。后端接受 `use_knowledge` 布尔开关（默认 false），页面固定发送 true，读取授权知识库并校验来源编号；false 仅保留为内部兼容 API；客户端不能指定资料、模型或密钥。文档段须有有效引用，AI 补充段无文档引用；普通 AI 回答无文档来源。两种模式均未接入联网搜索，模型知识未联网核实。

配置与接口细节见 [开发说明](docs/DEVELOPMENT.md)，验证记录见 [DeepSeek 接入验收](docs/DEEPSEEK-QA.md) 、[混合回答验收](docs/HYBRID-ANSWER-QA.md) 和 [多轮与口语追问验收](docs/FOLLOW-UP-QA.md)。

## 资料使用边界

页面不再提供共享资料上传及移除面板。后端资料 API 保留单文件 10 MB、UTF-8 文本和角色权限校验；既有资料继续供问答检索。通用 PDF / Word 知识库解析仍未接入。

内置基础资料由指定 Word 原文件一次性导入，支持阅读、下载和原文检索。更新内置资料的方法见 [开发说明](docs/DEVELOPMENT.md)。

发送默认检索真实资料并由 DeepSeek 回答，正文引用可打开同次服务端召回对应的完整原文；页面自动加载资料，不再需要勾选开关。知识库模式按标题分块做语义召回，并按功效等明确字段聚焦相关内容；低于相似度阈值的片段不用于回答，未命中不调用回答生成。默认已接入本地向量语义检索；旧关键词 RAG 不再作为运行入口，`RAG_ENABLED=false` 会拒绝启动。首页不预置模拟文件或陈皮回答，检索结果只引用真实资料。回归记录见 [检索修复验收](docs/RETRIEVAL-QA.md)。聊天记录只在当前页面内保留，退出或刷新后清除；追问上下文按发送模式隔离。
