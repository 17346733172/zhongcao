# 本草知问 · 中药知识库问答

最近归档快照：**V2.0（2026-11-11）**，对应 [GitHub V2.0 分支](https://github.com/17346733172/zhongcao/tree/V2.0)。本版在本地 Qwen3 + FAISS 向量 RAG 基础上，包含处方检查与仿真平台上传、片数计量、资料与处方统一入口，以及接入仿真平台的只读数据中心。

面向整理中药资料并据此提问的用户。按用户最新 DeepSeek 排版参考采用浅灰侧栏、白色主区和统一无衬线字体，提供 **Python / FastAPI 后端、真实登录、角色权限和 DeepSeek 资料问答**。

## 当前功能

- 左侧「数据中心」已接入煎药仿真平台：简约白底弹窗展示处方 / 批次指标、配发袋数、设备占用与故障、报警历史和全部处方分页。处方可展开药材每剂量 / 总量、片数与实测重量、煎法、工艺参数、审核、备注和关联批次。概览与设备每 15 秒更新，处方在进入、筛选、翻页或点击刷新时读取；失败明确提示。读取目标与处方上传共用后端 `DECOCTION_*` 配置，展示的是当前连接实例的仿真数据，见[数据中心验收](docs/DATA-CENTER-LIVE-QA.md)。

- 账号密码登录、退出、个人改密；登录会话默认有效 8 小时。
- 管理员创建账号、分配角色、停用 / 启用账号、重置密码。无公开注册，无默认密码。
- MD / TXT 文本保存到 SQLite 共享知识库，刷新和服务重启后仍可读取。
- 页面不再提供「原文检索」开关（[本地验收](docs/DEFAULT-RAG-QA.md)），点击发送或按 Enter 默认使用 Qwen3 + FAISS 检索 `code/data` 的 Markdown 与共享文本，再由 DeepSeek 整理回答。每轮只显示 AI 回答或状态提示，不再追加独立原文摘录；点击正文引用编号可查看对应完整原文。
- 回答优先使用资料，资料之外的一般知识单独标为「AI 补充，非文档原文」，不挂文档引用。AI 正文编号打开对应原文，回答与原文结果下方不再显示「引用资料」卡片，正文引用编号仍可打开完整原文。
- 当前会话保留最近 5 轮知识库追问；「陈皮」后问「作用？」会承接陈皮，明确换药材时切换主题，新建对话使用空上下文。口语 / 错字可先理解后重检，意思不明确时先澄清。
- 未命中的自然语言可整理后重检，仍无资料时不生成回答；数字无意义输入不调用模型，不返回无关片段或示例引用。两路均无内容只显示一条提示。
- 页面进入后自动读取资料；加载失败提供重试，发送失败保留问题。生成正文保留分节、引用和 AI 补充标签，隐藏重复总标题；移除独立原文摘录的文件名、正文和额外复制按钮，已有会话同步生效，见[原文摘录隐藏验收](docs/ORIGINAL-EXCERPT-HIDDEN-QA.md)。
- 「你好」等纯问候直接显示本地欢迎回复，不调用模型或检索、不占用追问历史；带实际问题的问候正常查询。
- 当前页历史会话、原文查看、复制；引用区域与回答卡片左边缘对齐，适配桌面和手机。生成失败保留问题，切换会话取消旧请求。
- 点击左侧「中药资料与处方」，在同一弹窗内切换「基础资料 / 处方检查」。基础资料保留《中药基础知识（详解版）》全文、章节定位与 Word 下载；切换标签保留阅读位置、处方输入和检查结果，不影响当前对话与草稿。正文与下载均需登录。

| 角色 | 查看资料与提问 | 添加 / 移除资料 | 创建账号与分配权限 |
| --- | --- | --- | --- |
| 普通用户 viewer | 是 | 否 | 否 |
| 编辑员 editor | 是 | 是 | 否 |
| 管理员 admin | 是 | 是 | 是 |

权限由 FastAPI 每次请求校验。角色调整、账号停用和密码重置会撤销该账号的所有旧会话；修改自己的密码后也需要重新登录。

**当前页面默认使用原文检索 + AI 的 Qwen3 / FAISS 向量 RAG。** 通用 PDF / Word 上传解析、会话持久化、流式回答和线上部署仍待接入。已保存文本供本系统所有登录用户查看，暂不区分个人知识库或租户。

## 处方检查 Agent

登录后点击左侧「中药资料与处方」，切换到「处方检查」。支持 TXT、MD、DOCX、PDF、PNG、JPG、WEBP，每次一份处方，单文件 10 MB，PDF 最多 8 页；也可粘贴文字或手动录入。关闭整个弹窗后清除本次处方。

后端使用 **LangGraph** 编排读取、意图识别、结构化提取、人工核对、规则检查和报告。图片与扫描 PDF 通过本地 RapidOCR 识别，文字经现有 DeepSeek 配置识别意图并提取字段；非处方或多个处方版本会要求补充。表格中紧邻「性别」标签的单字可按字段单独补识别。用户逐项核对药名、剂量、单位与每剂量口径后才能检查，修改后需再次确认。

按用户已明确的要求，处方默认按「每一剂的量」检查。上传与核对页显示「本方剂量口径」：选择随提取请求、药物表格、后端检查和报告完整传递，新增药行继承当前口径；不再要求额外点击每剂量确认按钮。药量数字不变，仍须核对原文后勾选确认；可改为总量或逐味设置。

信息不完整时，3.1 结论下会直接列出本次需补充的具体项目，例如患者年龄、过敏史，或第几味药的剂量、单位、口径；已提供的字段不重复要求补充。点击「去补充信息」可保留已有数据并定位第一个缺失字段，补充后再次确认检查，已补齐项自动从清单移除；复制报告也包含该清单。仍可通过「修改数据后复查」调整其他数据。

从报告点击「修改数据后复查」或「去补充信息」时，系统定位首个缺失字段，并用红框标出本次仍需补充的输入项。补齐一个字段，红框立即恢复为常规边框。识别服务已配置时，打开处方检查会在后台预加载本地 OCR，减少首次点击识别后的等待。

报告按用户给出的五节审核意见格式输出：**3.1 审核结论、3.2 主要问题、3.3 毒性药材与煎法核查、3.4 其他核查、3.5 处理建议**。结论加粗，正文使用条目，处理建议使用编号及子项；去掉原来的计数、卡片、明细折叠与范围面板。内容按当前处方生成，复制为同样的 Markdown 分节正文；格式及验证见[分节报告验收](docs/PRESCRIPTION-REPORT-QA.md)。3.1 由系统直接给出「通过 / 不通过 / 待补充信息」及具体判断依据。已接入十八反、人参—五灵脂十九畏、采用参考剂量和特殊煎法；普通用药提醒不自动阻断通过。新增依据与示例验证见[系统判定验收](docs/PRESCRIPTION-DECISION-QA.md)。

检查基本信息缺失、非法数值、单位、重复饮片、有限十八反配伍、部分特殊煎法及本地资料参考剂量。报告附依据与复核提示，支持复制；「通过」只表示本次已确认数据在系统覆盖项目内通过辅助审核，不代表完整临床安全评估或实际调配授权。尚未接入完整现行药典数据库、全部十九畏 / 妊娠禁忌、西药相互作用及诊断适宜性审核。

处方不写入共享知识库，不持久化原文件或报告；关闭弹窗后需重新上传。上传页说明模型处理范围；明显姓名、号码等字段会在发送模型前作基础遮盖，但仍应由用户先脱敏。无需新增模型密钥，复用后端 DeepSeek 配置；未配置时可手动录入并运行数据检查。依赖安装使用 requirements.txt 指定的官方 PyPI，OCR 模型随依赖提供，无需另行配置图片识别服务。详见[处方 Agent 说明与验收](docs/PRESCRIPTION-AGENT.md)。

检查结果页可点击「上传到仿真平台」，将总剂数和逐味药材明细录入煎药流程仿真平台。平台保存匿名处方并等待人工审核。上传支持 1–30 剂、克、毫克或片及常规、先煎、后下、包煎；总量按剂数均分，工艺采用仿真平台默认值。片数按计数单位原样传递，例如每剂 3 片、5 剂仍为每剂 3 片，平台显示合计 15 片；不会把 3 片当成 3 克。平台审核时补充每剂实测克数后才能计算水量和创建批次；接收端须同步更新计数单位协议。校验失败时，提示内的「确认药材」可返回核对页并定位对应药物行，保留数据，修改后需重新勾选确认并检查，再上传。默认连接本机 `http://127.0.0.1:8080`，其他部署地址或 API Key 在本草后端配置。见[仿真上传配置](docs/DEVELOPMENT.md#仿真平台上传)。

片数协议与桌面 / 手机流程的验证结果见[片数计量验收](docs/COUNT-UNIT-QA.md)。

仿真平台的本机实例与服务器实例各自保存处方。连接服务器时，在 `backend/.env` 将 `DECOCTION_BASE_URL` 设置为实际服务入口；HTTP Basic 网关认证通过 `DECOCTION_HTTP_USERNAME` / `DECOCTION_HTTP_PASSWORD` 配置，修改后重启本草后端。

对接代码位于 `backend/app/integrations/decoction.py`，接口、字段对应、认证和排障见[两个项目的后端对接说明](docs/DECOCTION-INTEGRATION.md)。

上传遇到网络超时或连接中断时，后端最多尝试 3 次，每次沿用同一处方编号；页面最多等待 120 秒。仍未确认时保留报告，可再次点击上传。平台按编号防止重复录入。

## 页面排版

桌面采用可收起侧栏与白色聊天区。新会话显示居中的欢迎语和圆角多行输入框，发问后输入框移至底部；右上角「知识库资料」打开共享资料抽屉：管理员 / 编辑员可上传、查看、移除资料，普通用户可查看；抽屉不再重复提供处方入口。入口分工及验证见[资料入口验收](docs/KNOWLEDGE-ENTRY-QA.md)。回答、标题与正文统一无衬线字体，引用和 AI 补充标识保留。手机提供导航与资料抽屉。视觉参考与验收见 [设计规范](DESIGN.md) 和 [视觉验收](design-qa.md)。

账号区、知识库 / 历史标签、顶部标题、上传按钮与底部说明按最新字体参考统一使用本地 DM Sans 搭配系统中文字体；主标签桌面 18px、手机 16px，辅助文字 14px，均采用常规字重。字体文件与开放许可位于 frontend/public/fonts，页面无需连接外部字体服务。

回答正文按用户提供的 DeepSeek 截图调整为 16px、1.75 行高，标题采用清晰的加粗层级，阅读列最大宽度 800px；来源小标签与标题同排。生成正文支持段落、加粗、列表、引用、代码和表格，原文在引用弹窗中保持原字面文本；窄屏表格可单独滚动，复制保留 Markdown 与来源标识。普通 AI 和知识库模式均向模型说明按需使用这些排版，不改变资料与 AI 补充的边界。对照与验证见 [视觉验收](design-qa.md)。

## 前后端分离

- `frontend/`：Next.js / React / TypeScript，负责登录、知识库和账号管理界面，独立安装依赖和启动。
- `backend/`：Python / FastAPI，负责认证、权限校验、账号和资料 API 及 SQLite，独立安装依赖和启动。
- 前后端通过 HTTP API 通信；本地由 Next.js 将 `/api/*` 同源代理到 FastAPI，业务逻辑和数据库访问集中在后端。前端通过服务端 `BACKEND_URL` 配置后端地址。

## 本地运行

环境：Python 3.11+、Node.js 20.9+、pnpm 11。

1. 双击根目录 **启动后端.cmd**。首次运行会建立独立虚拟环境、安装依赖，并提示设置管理员账号与密码（至少 10 位，输入时不显示）。保持终端开启。
2. 双击 **启动前端.cmd**，保持终端开启。
3. 打开 [登录页面](http://127.0.0.1:3000/login)，使用刚设置的账号登录。从左下角「账号管理」创建其他账号并分配角色。

两个脚本均支持 `--check` 检查运行环境。后端接口文档：[Swagger UI](http://127.0.0.1:8000/docs)。写接口需要 `X-CSRF-Protection: 1` 请求头；浏览器客户端已自动携带。

手动启动后端：

```powershell
cd D:\本草\backend
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.cli create-admin
.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --no-proxy-headers
```

另一终端启动前端：

```powershell
cd D:\本草\frontend
pnpm install --frozen-lockfile
pnpm dev
```

可将 backend/.env.example 复制为 backend/.env 修改数据库位置、允许来源及 Cookie 配置；启动时自动读取，已有系统环境变量优先。frontend/.env.example 可复制为 frontend/.env.local 修改服务端 `BACKEND_URL`，修改后须重启开发服务或重新构建。不要将密码和实际 .env 提交到 Git。

## 本地向量知识库 RAG

只使用今天接入的 Qwen3 + FAISS 向量 RAG，旧关键词检索入口已停用。新增查询向量缓存，以及按账号隔离、120 秒有效的已校验回答缓存；相同问题、上下文和检索原文未变时省去重复计算。提速说明见 [RAG 性能验收](docs/RAG-PERFORMANCE-QA.md)。

后端现在默认先加载并预热本地向量模型，再提供 API；终端出现 `Local vector RAG ready` 后即可使用。本机本次启动准备为 48 秒，期间无需重复启动。CPU 默认保留原始 BF16 权重，逐层以 FP32 计算，减少常驻内存；保持原模型、查询指令和现有索引。可用 `EMBEDDING_CPU_STORAGE=fp32` 对照；`RAG_WARMUP=false` 会恢复延迟初始化，首条提问需承担初始化耗时。

按用户参考项目组织为 `code/data`、`code/db`、`code/RAG` 和 `code/main.py`。指定的 69 页 PDF 已逐字校验后导出 Markdown，保留 7 张表格，原件与校验记录统一位于 `code/data`。知识库使用本地 Qwen3-Embedding-0.6B + FAISS；普通 AI 模式保持隔离。

首次使用先安装后端依赖，运行 `backend\.venv\Scripts\python.exe code/download.py --source modelscope`（或默认 Hugging Face），再运行 `backend\.venv\Scripts\python.exe code/main.py --rebuild`，完成后重启后端。模型和生成索引不提交到版本库；后续新增 Markdown 放进 `code/data`，共享上传文本继续参与检索。完整配置、终端问答、索引更新和兼容模式见 [RAG 说明](docs/RAG.md)，实际验证见 [RAG 验收](docs/RAG-QA.md)。

## 配置 DeepSeek

将 backend/.env.example 复制为 backend/.env，在本机填写 DEEPSEEK_API_KEY；不要在聊天或源码中发送密钥。默认 DEEPSEEK_BASE_URL=https://api.deepseek.com、DEEPSEEK_MODEL=deepseek-flash，均可由后端配置。保存后重启后端，刷新页面；发送默认检索原文并生成 AI 回答，无需选择按钮。未配置时显示配置提示，请求失败保留草稿。

密钥仅在后端读取。页面每次发送当前问题、知识库模式最近 5 轮摘要及最多 3 个检索片段；未命中的自然语言可能先单独进行语义整理，再重检资料（额外一次模型请求）。每轮摘要的问题最多 500 字符、回答最多 1000 字符；向量分块默认 500 字符、重叠 50，最多 3 段；保留 3000 字符的服务端片段上限。后端接受 `use_knowledge` 布尔开关（默认 false），页面固定发送 true，读取授权知识库并校验来源编号；false 仅保留为内部兼容 API；客户端不能指定资料、模型或密钥。文档段须有有效引用，AI 补充段无文档引用；普通 AI 回答无文档来源。两种模式均未接入联网搜索，模型知识未联网核实。

配置与接口细节见 [开发说明](docs/DEVELOPMENT.md)，验证记录见 [DeepSeek 接入验收](docs/DEEPSEEK-QA.md) 、[混合回答验收](docs/HYBRID-ANSWER-QA.md) 和 [多轮与口语追问验收](docs/FOLLOW-UP-QA.md)。

## 资料使用边界

单个文本文件最多 10 MB，采用 UTF-8 编码。空文件、超限、无权限和保存失败有明确反馈。PDF / Word 显示「未上传 · 待接入解析服务」，不会伪造成功。

内置基础资料由指定 Word 原文件一次性导入，独立于右侧上传列表；通用 Word 上传解析仍待接入；内置资料支持阅读、下载和关键词原文检索。更新内置资料的方法见 [开发说明](docs/DEVELOPMENT.md)。

发送默认检索真实资料并由 DeepSeek 回答，正文引用可打开同次服务端召回对应的完整原文；页面自动加载资料，不再需要勾选开关。知识库模式按标题分块做语义召回，并按功效等明确字段聚焦相关内容；低于相似度阈值的片段不用于回答，未命中不调用回答生成。默认已接入本地向量语义检索；旧关键词 RAG 不再作为运行入口，`RAG_ENABLED=false` 会拒绝启动。首页不预置模拟文件或陈皮回答，检索结果只引用真实资料。回归记录见 [检索修复验收](docs/RETRIEVAL-QA.md)。聊天记录只在当前页面内保留，退出或刷新后清除；追问上下文按发送模式隔离。
