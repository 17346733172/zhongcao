## 最新接入：OpenVINO FP32 文字识别

## 本次实际改动

- 后端在配置识别服务、且 OCR_WARMUP 开启时，在 API 就绪前对内存合成页执行一次完整推理；预热失败可以重试，重复进入处方页不会重复预热。未配置识别服务时不初始化 OCR。
- 当前 RapidOCR 1.2.3 没有直接暴露 ONNX 会话线程选项，适配器使用相同模型路径和原图优化选项替换该实例的会话。每个 CPU 会话最多 4 线程，关闭线程空转；不修改依赖文件、全局构造函数、输入分辨率、方向分类或原文核对规则。
- 日志记录转换、排队、初始化、检测、方向分类、文字识别，以及整个 prepare 图的耗时。数字日志不包含处方正文或密钥。
- 新增 OCR_WARMUP 配置示例。无前端界面变动，没有新增依赖。

## 实测与限制

环境为 i5-10200H、4 核 / 8 线程、约 8GB 内存，CPU 推理。比较输入为项目内 3508×2479 的虚构整页处方及用户提供的局部截图，未调用云模型。

- 默认配置整页首次调用：13.979 秒；新配置合成页预热后的整页首次调用：13.463 秒。本次首次整页收益有限，不能把重复图的 8 秒耗时宣传为所有图片首次上传的保证。
- 新配置后续整页 read_upload：8.738 秒；局部截图 OCR：2.803 秒。
- 两张图的全部 OCR 文本框文字与默认配置逐项一致：整页 110 框、局部 21 框。合成页预热约 5.93 秒，计入后端启动准备时间。
- 更小的合成页预热未明显改善整页首次识别，已调整为 A4 页比例及长短文字混合。改变识别批大小到 1 后发现文字与基线不同，未采用该调整。
- 本次测试没有证明任意新图都能稳定在 8 秒内。新图尺寸、文字宽度分布、系统负载与空闲后的内存换页仍可能增加耗时；意图识别及字段提取的 DeepSeek 时间另计。
