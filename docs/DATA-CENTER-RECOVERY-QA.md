# 数据中心连接池与断线自动恢复

日期：2026-11-13。

## 故障证据

用户再次反馈“平台数据更新失败”，实际服务日志持续出现 `PoolTimeout`。新建客户端对相同平台的统计、报警和运行批次可完整读取，约 0.45–2.54 秒，说明当时通路已经可用，原后台仍困在旧连接池中。

核对本机安装的 httpx 0.28.1 / httpcore 1.0.9：HTTPS 代理 CONNECT 成功后，如果 TLS 握手失败，长期使用的连接池可能留下不可复用的活动连接。原后台跨刷新轮次始终持有同一客户端，重试仍使用原池，失败累积到连接上限后持续等待空位，网络恢复也不会自行恢复。

使用仅在本机运行的故障代理，返回 CONNECT 200 后立即断开，并将原客户端池容量缩小为 2。五个连续请求的真实结果为 `ConnectError, ConnectError, PoolTimeout, PoolTimeout, PoolTimeout`。没有接触真实平台、关闭 TLS 校验或修改系统网络设置。

证据：[连接池耗尽复现](../design/data-center-recovery-qa/pool-exhaustion-reproduction.json)。

## 修复

- 连接只在一轮刷新内复用，本轮结束关闭客户端，后续轮次使用新池。
- 任何传输异常先关闭失效客户端，再重建后重试，不沿用可能失效的代理隧道或连接池。
- 最大连接数 4、最大保活连接数 2；池等待最多 2 秒、客户端清理最多 2 秒；原网络整轮 45 秒截止和轮次间 15 秒间隔保留。
- 成功才更新数据和真实读取时间；失败继续保留旧数据与错误说明，不隐藏红色提示来冒充修复。
- 新增每轮 `success / failed / cancelled` 及耗时日志，避免只看本机状态接口 200。日志不含凭据、异常原文或处方内容。
- 没有升级或修改第三方依赖，没有新增环境变量，没有变动平台处方或运行状态。

## 回归与恢复验证

- 完整后端回归 155 项通过。
- 新增 PoolTimeout 后使用新客户端重试成功；验证所有旧客户端关闭、日志不输出异常原文。
- 真实本机故障代理连续六轮造成 12 次握手失败，均回收客户端，没有累积为 PoolTimeout；恢复成功数据传输后，同一 reader 重新取得数据。
- 整轮截止测试追加验证取消后客户端已关闭，后续刷新可重新成功。
- 本轮没有前端源码改动，没有重复构建；重新执行真实平台浏览器流程。

自动恢复另用隔离的本机字节中继验证。健康时将 CONNECT / TLS 字节转发到既有代理，使用真实平台、正常认证和 TLS 校验；故障时只断开这个验收进程的握手，不影响实际本草服务。

同一后台任务于北京时间 17:40:29 取得真实数据，随后自然定时刷新连续两轮失败（四次握手失败），原数据时间保持不变。中继恢复后，后台于 17:41:20 自动取得新平台数据并清除错误，仿真时钟继续前进。没有点击刷新、调用手动唤醒或重启 reader / 后端。

证据：[无需重启的真实数据自动恢复](../design/data-center-recovery-qa/automatic-recovery-result.json)。

## 浏览器与实际服务

1440 / 390 / 320px 真实 Next.js 页面通过临时认证后端读取真实平台，统计自动 / 手动更新、设备、处方分页及按需批次详情均通过。没有业务响应替身，没有创建平台测试处方；桌面与手机截图已目视核验，显示“平台数据已更新”，没有数据中心错误提示。

结果：[真实浏览器结果](../design/data-center-recovery-qa/browser-result.json)。

截图：[桌面概览](../design/data-center-recovery-qa/real-live-overview-1440.png)、[390px](../design/data-center-recovery-qa/real-live-overview-390.png)、[320px](../design/data-center-recovery-qa/real-live-overview-320.png)、[手机真实批次详情](../design/data-center-recovery-qa/real-live-detail-320.png)。

实际 8000 服务已重启加载单轮客户端修复。北京时间 17:41:31–17:46:43 连续观察 312.87 秒，取得 17 次不同时间的真实平台数据；17 条每轮成功日志、0 次刷新失败、0 次 PoolTimeout，单轮最长 7.212 秒。仿真时钟从约 670,984 秒持续前进到 671,296 秒，统计为 30 张处方、129 台设备。

证据：[实际服务五分钟结果](../design/data-center-recovery-qa/live-service-result.json)。

观察结束后服务继续成功更新，原启动入口确认登录页、8000 健康接口及 3000 API 代理均正常。本次验证同时覆盖了真实持续运行与断线后无需重启的恢复能力；外部平台或代理真正不可达时仍会明确报错，不将缓存伪装成新数据。
