# 测试方案读取失败恢复验收

日期：2026-11-17。

用户截图同时出现旧版只读说明和读取失败。实际本草日志显示独立 `GET dashboard` 发生 `ConnectTimeout`，同一时段共享快照仍成功更新。原默认用时页在探测 404 后再次独立请求 dashboard，增加了失败机会，且错误后只能手动重读。

本次旧平台优先复用共享设备数据及原读取时间；只对 GET 传输失败重试一次，整轮最多 40 秒，不改变保存单次提交规则。真实 404 仅缓存 60 秒，手动重新读取强制重新探测；探测失败但有共享值时返回 `supported=null / capability_pending=true`，不把连接失败误判成不支持修改。过期值保留原时间并标记，页面每 15 秒自动重读，连接错误与只读说明合并展示。

- 前端 `pnpm typecheck`、`pnpm test` 通过，33 项现有回归通过；最终隔离副本 `pnpm build` 通过。此前构建曾因既有 Next.js 安全升级提示中止，重试通过；本次未升级依赖，临时副本使用共同 Turbopack 根目录，生产配置未变。
- 本草后端 `.venv/Scripts/python.exe -m unittest discover -s tests -p test_device_defaults.py -v` 通过，共 9 项。其中 5 项读取恢复回归覆盖共享值免额外请求、原时间保留、过期时独立读取失败两次后保留、探测失败与未知能力区分、手动确认绕过缓存、无数据不报空成功；保存单次确认及鉴权 / CSRF 原回归仍通过。未运行完整后端套件。
- 最终开发及隔离生产页面通过 1440 / 390 / 320px 浏览器检查：200 但 stale 的结果及 HTTP 502 均可在 15 秒后自动恢复，保留原值和草稿，错误清除；无首次数据时自动恢复后显示卡片。未知修改能力仅显示待确认提示，确认旧版后继续禁用保存。
- 连接失败与只读原因只显示一个反馈区域；保存冲突不会自行触发重新读取或重复写入。关闭取消恢复计时，已有输入校验、分钟换算、保存期间锁定、还原、并发版本、AI Agent 草稿及手机无整体溢出均通过。无页面脚本错误，桌面和 320px 生产截图已查看；临时生产服务已关闭。
- 本草本机后端已重启就绪，8000 健康检查 200，8000 与 3000 代理的新接口均保留匿名 401。真实只读连续两次返回 13 类默认值，`stale=false / error=null`，两次 fetched_at 均为共享快照的同一原时间；上游仅一次 `GET device-defaults`，未额外读取 dashboard，未向真实平台写入或重启仿真服务器。
