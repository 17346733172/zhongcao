# 枚单位仿真上传验收

日期：2026-11-12。

本轮修复用户上传「大枣 3 枚」时出现的“单位暂不支持仿真上传”。之前只在识别与核对中支持枚，上传端和接收端只支持克、毫克与片。

## 行为与边界

- 本草上传转换将枚映射为 `unit="item"`，片继续为 `unit="piece"`；均使用 `quantity_per_dose`，两个单位独立保存与显示，不互相改写。
- 每剂量保持原数字；总量除以剂数。例如 5 剂、总量 15 枚，上传为每剂 3 枚，平台合计显示 15 枚。
- 平台接收、PostgreSQL JSON 持久化、处方明细、追溯、手动录入与称重审核统一支持枚。手工切换枚 / 片 / 克会清空旧数量，防止单位切换后沿用旧值。
- 审核通过前分别为枚数、片数饮片补充每剂实测总克数。原计数和单位保留；未称重不能审核通过或创建批次，水量只按实测克数计算。
- 本草报告上传说明和数据中心分别显示枚、片及实测重量；无效数量仍拒绝，旧接收端拒绝新单位时明确提示，不显示虚假成功。
- 不新增依赖、不迁移历史数据库，不自动上传当前报告或创建生产测试处方。

## 验证

- 本草后端完整 141 项回归通过，新增覆盖在现有上传业务用例中：枚 / 片独立传递、总量均分、非法数量拒绝及旧平台错误；后续数据中心枚数透传的 6 项定向回归通过。
- 平台后端完整 52 项回归通过，使用单独临时 PostgreSQL：枚数保存并重新读取、未称重审核拒绝与事务不变、只补片数而漏枚数时拒绝、枚 / 片称重后保留计数及批次实重计算。
- 平台首次回归因 WSL 空闲关闭临时数据库而中断；保持 WSL 会话、重启该临时容器后完整重跑通过。未修改原有数据库或降低校验。
- 本草 `pnpm typecheck`、31 项 `pnpm test` 和独立副本 `next build --webpack` 通过；平台 5 项 `npm test`、`npm run build` 通过，仍有原有大 chunk 提示。
- Headless Chrome 1440 / 390 / 320px 通过真实 Next.js 代理、本草 FastAPI、平台 FastAPI、PostgreSQL 联调，无业务 API 替身，无模型调用。使用临时账号、SQLite 和独立数据库。
- 每个宽度验证“大枣每剂 3 枚、生姜每剂 3 片、陈皮每剂 9 g，共 5 剂”的录入、人工确认、上传、平台显示、称重审核、创建批次。实测演示重量分别为 6 和 4.5 g/剂，批次总质量为 `(6+4.5+9)×5=97.5 g`；仅为测试数字，不是换算标准。
- 验证 390px 平台手动选择枚单位与枚 / 片 / 克切换清空旧值；无页面异常，审核弹窗在屏幕内可操作。桌面枚数和 320px 称重截图已目视核验。

证据：[真实联调结果](../design/item-unit-qa/result.json)、[本草 320px 上传成功](../design/item-unit-qa/bencao-320-uploaded.png)、[平台每剂 3 枚 / 合计 15 枚](../design/item-unit-qa/platform-1440-items.png)、[320px 称重审核](../design/item-unit-qa/platform-320-review.png)。

本草数据中心额外通过 1440 / 320px 真实隔离后端展示核验：每剂 3 枚、合计 15 枚与每剂实测 6 g 分列显示。该补充使用当前 Next.js 页面，将浏览器 API 请求转发到真实临时后端，未模拟业务响应。证据：[数据中心结果](../design/item-unit-qa/data-center-result.json)、[320px 数据中心](../design/item-unit-qa/data-center-320.png)。

## 生效记录

已更新用户当前连接的服务器前后端，并保留旧镜像与 PostgreSQL 备份。发布时确认备份有效，切换后的前后端健康检查通过；SSH 回执中断后，改由实际 HTTPS 网关独立核验：Herb 单位包含 g / piece / item，新版静态资源入口与文件长度一致，混合枚 / 片的校验请求只因故意重复药名而返回 422，未增加生产处方。完整静态资源下载受链路超时影响，未将其记为已完成的远端文件哈希验证。

原有 24 张处方、24 个批次仍在，仿真恢复并保持更新前的运行状态。本草本机后端已重启，8000 健康、3000 登录页和 API 代理均就绪；前端保留现有开发运行方式。没有自动重传用户当前报告，用户保留报告后再次点击上传即可。

证据：[部署与入口核验](../design/item-unit-qa/deployment-result.json)。
