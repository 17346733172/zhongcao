# 数据中心连接路径修复验收

日期：2026-11-13。

后续用户仍反馈长期失败，进一步发现代理握手失败会让长期持有的连接池耗尽；本文件的五轮验证没有覆盖该故障。现行实现已补齐每轮关闭、失败重建及自动恢复测试，最新结果见[断线恢复验收](DATA-CENTER-RECOVERY-QA.md)。下文保留本次代理路径对照的历史证据。

## 根因与对照

用户再次反馈“平台数据更新失败”。前两轮调整了等待时间和缓存可用性，未解决实时更新链路；本次以实际平台数据持续更新为验收条件，不把本机快照状态接口返回 200 当成联网成功。

检查发现本机 Windows 浏览器已启用本地 HTTP 代理，但仿真后端请求使用 `trust_env=False` 且没有显式代理，一直直连公网平台，两者实际网络路径不同。

同一台电脑、相同平台地址和认证的只读对照：

| 路径 | 请求 | 结果 |
| --- | --- | --- |
| 后端原直连 | 健康接口 | 连接等待约 5 秒后超时 |
| 后端原直连 | dashboard | 2.89 秒收到响应头，响应体仅取得 28,513 / 34,214 字节，约 19 秒读取超时 |
| 既有本地代理 | dashboard | 两次完整成功，约 1.46 / 1.16 秒 |
| 既有本地代理 | 完整 simulation | 约 2.24 秒完整取得 197,289 字节 |
| 既有本地代理 | 处方第一页 | 约 0.79 秒完整取得 19,050 字节 |

这些是本次环境观测值，不是长期性能承诺。对照表明，现有代理路径能正常取得相同平台的完整数据，之前仅延长直连等待无法消除故障。

## 修复

- 新增后端 `DECOCTION_PROXY_URL`，默认留空仍直连；本机实际配置为已启用、经对照验证的代理入口。
- 统计后台刷新、处方分页、单个批次详情及处方上传统一使用此配置。
- 保留 `trust_env=False`，只使用明确配置的代理，不全局接受环境 / 系统代理；TLS 证书校验和平台认证保持启用，不影响 DeepSeek 请求。
- 代理入口只接受 HTTP / HTTPS，不接受内嵌账号、额外路径、查询或片段；非法配置不回显原始值。配置不返回到前端，日志只显示 `Simulation transport=configured proxy`。
- 示例留空，并提供 `PORT` 占位注释。真实 `.env` 继续由 Git 忽略，没有新增依赖，也没有修改系统代理或远端服务器配置。

## 自动验证

后端完整 `.venv/Scripts/python.exe -m unittest discover -s tests -v`：153 项通过。

新增覆盖显式代理默认关闭、服务端环境加载、配置拒绝与错误脱敏、上传保留显式代理及禁用环境代理；现有读取和后台客户端测试也断言代理正确透传。其他认证、处方、RAG 与快照缓存回归均通过。

本轮未修改前端源码，没有重复运行前端生产构建；前端沿用上一轮已通过的类型检查 / 构建结果，并重新进行真实平台浏览器验收。

## 实际本机服务连续更新

本草后端通过原独立启动入口重启，模型预热完成后启动日志确认 `Simulation transport=configured proxy`。登录页、8000 健康接口和 3000 API 代理均正常。

直接观察实际 8000 服务的缓存文件，仅在成功读取平台后该文件才会更新。连续取得五个不同的新时间：北京时间 16:51:36、16:51:55、16:52:14、16:52:33、16:52:55。相应仿真时钟从约 667,990 秒推进到 668,067 秒，包含 30 张处方、129 台设备，证明数据来自持续推进的平台，不是反复读取旧缓存或制造新时间。

五轮检查结束后再核对，本机缓存继续更新到 16:54:40，仿真时钟约 668,172 秒。期间曾有一次可恢复的连接超时重试日志，后续真实读取继续推进；没有将外网连接描述为永久无故障。

证据：[实际服务连续更新](../design/data-center-proxy-qa/live-service-result.json)。

## 浏览器核心流程

使用当前真实 Next.js 页面，业务请求转发至使用相同平台配置与代理的临时 FastAPI / SQLite 登录账号。统计、设备、处方、批次均从实际仿真平台读取，没有业务响应替身或故障模拟，没有向平台添加测试处方，也没有调用模型生成。

- 1440px：三个不同的平台成功读取时间，其中包含定时自动更新；数据中心错误提示消失。
- 1440 / 390 / 320px：初次读取、手动更新后取得新时间、设备标签、真实处方分页和按需批次追溯详情均通过，无页面异常或整体横向溢出。
- 桌面与手机截图已目视核对，状态为“平台数据已更新”，统计与活跃批次可正常展示。
- 首次脚本在接收到新状态后立即检查页面全局 alert，早于 React 提交且范围过宽；已改为等待数据中心自身的错误区域消失，最终完整脚本通过。
