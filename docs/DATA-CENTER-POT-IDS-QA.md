# 锅号与设备编号查询验收

日期：2026-11-13。

## 修复

用户截图中单独发送「锅号」得到资料不足，因为运行查询识别只包含「编号」而漏了「锅号」。现在锅号与煎药锅设备编号同义，保留平台原始ID，例如 `pot-49`，不另建数字编号。

- 「锅号」「查锅号」「锅编号」「设备编号」读取数据中心真实设备明细，不进入药材检索或模型。
- 在「现在有几个锅在工作」后问「锅号 / 设备编号 / 编号呢」，保留上一轮设备类型和状态，重新使用当前快照；「全部锅号」清除状态范围。
- `pot-49`、`锅号 pot-49`、`查设备编号：POT-49` 精确匹配同一ID，显示真实状态、名称、类型、关联批次与未解除报警。询问某个ID是否故障时返回它的实际状态，不把非故障设备误报成不存在。
- 未知编号明确说明当前记录未找到，不编造0台或转回药材资料不足；过期快照保留时间说明，无快照不编造设备；控制命令仍只读拒绝，知识问题保持原有流程。
- 回答中的「查看数据中心」传递deviceId并预填「设备编号 / 锅号」精确筛选；输入忽略大小写、首尾空白，可清空恢复列表，与类型 / 状态筛选同时生效。报警区域继续由自身筛选独立控制。
- 编号列表沿用最多20条的聊天展示上限，超出提示打开数据中心查看全部；具体编号可直接查询，不受前20条限制。
