# 利用率运行问答验收

日期：2026-11-13。

## 问题与口径

截图原句「今天锅的利用率？」此前进入药材知识检索，得到未找到相关内容。现在识别为数据中心运行问题，复用同一真实设备快照，不调用药材模型。支持利用率 / 使用率、当前占用率、具体锅号、同主题与日期追问。

已核对仿真平台 `Service._device_views`：`utilization_percent` 是 `productive_seconds / (clock.now - added_at) × 100`，即设备加入后的累计有效工作占比。`engine.advance` 只在批次有效执行时累计工作秒数，设备占用与有效工作并不相同。平台返回的是累计值，当前本草历史事件统计也没有完整日边界工作时长，因此本次**没有实现准确的今日 / 周 / 月利用率**。

返回行为：

- 问今天 / 昨天 / 本周 / 近7天 / 本月 / 指定日期时，主标题明确不可准确统计对应时段，解释缺少完整起止记录。
- 下方只展示清楚标注的参考值：所选设备累计利用率的算术平均；读取时使用中台数 ÷ 所选设备总数得到当前占用率。两者不标为当天结果，未使用锅也计入全部锅的样本。
- 未指定日期时明确回答累计利用率或当前占用率；不把指标名「占用率」中的「占用」解析成只筛选busy设备，以免占用率错误成为100%。显式询问「使用中锅」仍按该范围统计。
- 支持「pot-49利用率」与接着问「今天的呢」，保留设备编号和时间语义，快捷入口打开同一设备。知识问题与设备控制边界保持原样。
- 未找到编号、没有设备样本、无快照、过期快照、无效百分比都有明确反馈；没有样本不补造0%，不把旧数据声称为实时。
- 设备表列名明确为「累计利用率」。没有新增接口、表、依赖或平台写入。

## 验证

- 完整后端194项通过，新增6项涵盖截图原句不走药材 / 模型、日期限制、不同指标与设备范围、编号及日期追问、未知 / 过期 / 无数据 / 非法值、知识分流与控制拒绝。
- 最终前端隔离复制到 `tmp/data-center-utilization/build`，`pnpm build --webpack` 通过（包含TypeScript检查）。前端仅改表头文本，未新增交互或依赖。
- Headless Chrome1440 / 390 / 320px，真实页面通过临时认证后端读取实际平台。没有业务替身和模型密钥，未修改真实账号或平台数据。
- 三种宽度均验证用户原句返回数据中心来源 / 读取时间、明确日期能力限制、累计与读取时参考分别标注；当前利用率 / 占用率问题、pot-49利用率与今天追问、设备定位、累计利用率表头、页面无整体横向溢出。

验收时50台煎药锅的累计利用率平均约0.57%，当前5台使用中、占用率10%。这些是读取时的真实累计 / 状态参考，**不是今天的利用率**，会随运行变化。
