# 片数计量与仿真上传验收

日期：2026-11-10。

本次修改覆盖本草与关联的「中药煎药流程仿真平台-dev」。处方检查沿用原有计数单位支持，仿真上传新增 `piece` / `quantity_per_dose`；克与毫克继续使用 `grams_per_dose`。

## 验证结果

- 本草后端完整回归：124 项通过，含片数原样传递、总量均分、无效数量拒绝和旧平台拒绝时的反馈。
- 仿真平台后端完整回归：42 项通过，使用单独启动的 PostgreSQL 17 测试容器；覆盖计数持久化、审核失败事务回滚、补实重、驳回和批次重量校验。
- 本草前端 `pnpm typecheck`、31 项 `pnpm test` 通过；独立源码副本执行 `pnpm build --webpack` 通过，避免覆盖正在运行的构建。
- 仿真平台前端 2 项 `npm test` 及 `npm run build` 通过。构建保留原有大体积 chunk 提示，无构建错误。
- 1440 / 390 / 320px，真实本草 API → 真实仿真 API → 独立 PostgreSQL 的浏览器流程通过，无页面脚本错误。本草页面无横向溢出，平台审核弹窗在各宽度内可操作，药材宽表在自身区域滚动。
- 平台手动录入半片，以及克 / 片切换后清空旧数量的浏览器核验通过。

## 核心案例

虚构流程处方含生姜每剂 3 片、陈皮每剂 9 g，共 5 剂。本草上传后，平台保存生姜每剂 3 片、合计 15 片、重量为空。未称重时不能审核通过或创建批次；在平台审核时填写生姜每剂实测总重 4.5 g 后，原始片数保持不变，仿真总药材质量为 `(4.5 + 9) × 5 = 67.5 g`。这些数字仅用于验证协议与计算，不是药材单位换算标准。
