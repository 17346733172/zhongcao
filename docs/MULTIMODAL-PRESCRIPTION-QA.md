# 处方多模态解析验收

日期：2026-11-12。图片与扫描 PDF 的当前实现；旧 [OCR 性能记录](OCR-PERFORMANCE-QA.md)仅供历史对照。

用户已明确允许将处方原始图片及扫描 PDF 页面图像发送到当前配置的 DeepSeek 官方接口。本机复用现有后端配置，接口为 `https://api.deepseek.com`，模型为 `deepseek-flash`；密钥未写入代码、文档、浏览器或日志。本轮真实接口测试只使用项目虚构演示处方。

## 当前路径与边界

- PNG / JPG / WEBP：本地校验格式、大小、像素数并规范化方向，再向视觉模型发送 JPEG 图像内容块。
- 扫描 PDF：PDFium 渲染页面；混合 PDF 保留原生文字，将缺少可读文字的页面图像和文字上下文一并提交。每份文件只请求模型一次。
- 图片路径为 `read_upload → parse_multimodal → confirm_data`。单次请求完成输入分类、文字转录和处方字段提取；非处方、多份处方或多个版本返回澄清。
- TXT / MD / DOCX、可读文本 PDF 与粘贴文字继续采用原生文字读取、意图识别和结构化提取。DOCX 内嵌图片仍提示单独上传。
- 不再导入 RapidOCR / OpenVINO，不再初始化、预热或回退至本地 OCR。移除其直接依赖及旧配置；已有环境中的旧包不必卸载。
- 图片字段与模型转录校验一致性，响应标记 `source.verification=model_transcription`。二者可能同时读错，不能当成对原图的独立验证。枚 / 片分别保留，不换算重量。
- 处方不上共享知识库，不持久化原文件 / 报告，不启用远程 tracing；内部图像编码不返回前端。图片中的身份信息须上传前自行遮盖，文字的基础标识遮盖不保证完全匿名。
- 上传页说明云端范围，核对页明确显示「模型转录」并提供原始图片和 PDF 对照。规则检查仍要求人工确认；改动字段后必须重新确认。模型失败保留文件供重试或手动录入。

限制保持为单文件 10 MB、PDF 8 页、文字 2 万字符。图片最多 1600 万像素、单帧；转换后最长边 8192 像素，扫描页渲染最长边 2400 像素，图像编码合计最多 40 MiB。模型单次等待 90 秒，浏览器识别等待 180 秒；网络、页面数、图像质量和服务负载会改变实际时间。

## 真实接口测量

通过生产用 `PrescriptionAgent.run(phase=prepare)`，计时包含文件读取、图像准备、真实云端请求、解析和一致性校验，不包含浏览器 HTTP 上传与渲染。每种输入各测试一次，不能代表稳定平均值或所有真实处方的识别正确率。

| 演示样例 2 | 扫描 PDF | 6.532 秒 | 12 | 全部匹配，含大枣 3 枚、生姜 3 片 | 1 |

- 前端 `pnpm typecheck`、`pnpm test`：类型检查和 31 项回归通过。
- 独立源码副本 `next build --webpack`：生产构建成功，不干扰正在运行的开发服务；`pip check` 无依赖冲突。
- Headless Chrome 在真实 Next.js 界面下验证 1440 / 390 / 320px。业务 API 采用隔离替身，提取响应使用上述真实云端演示结果，报告由实际本地规则生成；不使用真实账号，不写入数据库，不向仿真平台上传。

- 无页面异常，窄屏无整页横向溢出。桌面和 320px 截图已目视核验。

## 本机生效验证

本机后端已通过独立启动入口重启，启动日志显示 `Prescription image parser=DeepSeek multimodal model=deepseek-flash; local OCR disabled`，不再进行处方 OCR 预热。知识库 Qwen / FAISS 预热独立保留，不能将它误认为处方 OCR 仍在加载。

`scripts/start-local.ps1 -Check` 返回后端、登录页与 API 代理均就绪；`启动后端.cmd --check` 通过。原数据库、账号和前端服务保留，未新增开机自启或更改外部仿真数据。本轮真实模型测试在生产代码的处理图中执行；浏览器业务 API 使用替身，未使用真实患者文件完成线上端到端识别。

完整手写、低清、多页复杂排版准确率专项评测仍未执行；最终药物字段仍须对照原图人工核对。
