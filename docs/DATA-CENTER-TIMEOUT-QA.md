# 数据中心远程链路超时修复

日期：2026-11-13。

本文件记录首轮仅延长超时的排查结果。用户后续仍反馈长时间读取，现行实现已改为真实快照缓存和后台轻量刷新，见[最新验收](DATA-CENTER-CACHE-QA.md)。下文耗时与行为保留为历史记录。

## 原因

本草本机 8000 健康接口与 3000 API 代理均正常返回 200。原后端日志中数据中心快照连续返回 502；截图中的原提示只在 `httpx.RequestError` 分支出现。

使用现有后端连接配置只读复测仿真平台，确认链路间歇出现 `ConnectTimeout` 和 `ReadTimeout`。成功的快照完整读取耗时曾达 20.32 秒，处方第一页读取耗时 13.23 秒；返回数据通过本草响应模型校验，包含 25 张处方、129 台设备。旧后端连接等待 5 秒、读取等待 12 秒，页面 18 秒后取消，容易在远程链路波动时中断。

以上实测为本次环境的观测值，不是稳定性能承诺。

## 调整

- 只读快照与处方分页共用连接等待 10 秒、读取等待 20 秒；传输异常最多尝试两次。
- 第二次请求保留原分页、筛选与认证配置。HTTP 错误、认证错误和响应格式异常直接返回，不重复请求。
- 超时与无法连接分别提示，日志仅记录端点名称、尝试次数和异常类型，不记录异常原文、服务地址、凭据或处方内容。
- 页面等待上限改为 75 秒；关闭弹窗仍取消浏览器等待。概览下一轮读取在本轮结束 15 秒后发起，避免轮询重叠。
- 状态文字区分初次连接、更新、成功、失败；已有快照的失败保留原数据与最近成功时间，不再一直显示「正在连接平台」。

等待时间调整提高慢链路的恢复机会，未消除远程网络波动。连接长期不可达时仍会明确报错，不补造统计或处方。

## 自动验证

- 后端项目命令 `.venv/Scripts/python.exe -m unittest discover -s tests -v`：143 项通过。
- 数据中心新增回归覆盖连接 / 读取超时后成功、相同参数重试、持续失败最多两次、错误提示区分和日志脱敏；原 HTTP / 格式异常用例增加不重试断言。
- 前端 `pnpm typecheck`、`pnpm test`：通过，31 项回归。
- 复制当前前端源文件、配置和已有依赖到独立临时目录，执行 `pnpm build --webpack`：通过，避免影响实际开发服务缓存。
- `git diff --check`：通过。

## 浏览器验证

交互浏览器工具两次因 Windows 沙箱初始化失败无法连接，改用项目已有 Playwright 与 Headless Chrome。页面使用本机真实 Next.js，业务请求转发到临时 FastAPI / SQLite 验收账号；成功响应由该后端通过本次修复代码只读访问实际配置的仿真平台。未修改真实账号、处方、平台审核或运行状态，未调用模型生成。

- 1440 / 390 / 320px：初次读取失败、重试、真实概览与处方第一页均通过，25 张处方、129 台设备；无整体横向溢出或页面异常。
- 首次失败与 1440px 的额外 19 秒等待为浏览器本地故障场景，明确区分于真实平台状态。桌面重试约 36 秒、390px 约 31 秒、320px 约 66 秒后取得真实快照；后两者没有额外注入等待，隔离后端日志确实捕获了传输超时与重试。
- 1440px 额外验证已有快照时读取失败：保留统计、最近成功时间及过期提示。
- 三种宽度均验证处方第一页 20 条及 Escape 关闭。桌面和 320 / 390px 成功截图已目视检查，布局沿用原设计，状态文字可正常换行。

## 本机生效

修复完成后通过原独立后台启动入口重新加载本草后端；前端开发服务自动加载修改。新后端完成 Qwen / FAISS 预热（本次 59.50 秒），启动入口确认 8000 健康接口、3000 登录页及 API 代理均已就绪。重启后的实际服务日志也已出现 `/api/data-center/snapshot` 返回 200，确认真实页面轮询恢复读取。
