# 仿真控制功能验收

日期：2026-11-14。

按用户「这几个为什么是暗的，我需要用起来」的要求，接通新建测试任务弹窗中的生成演示数据、开始、暂停。

## 实现

- 生成接收1–50的严格整数，创建对应数量的匿名演示批次；逐次生成均新增。开始固定真实时间1倍速，暂停保留进度，控制目标为既有DECOCTION配置的仿真平台。
- 新后端接口沿用登录、knowledge:read及写入CSRF / Origin保护；三种角色可操作，与原处方上传的登录范围一致。所有网关凭据仅在后端使用。
- 前端提交中锁定控件并显示进度；运行时禁用开始，暂停时禁用暂停。状态使用平台直接响应和轻量dashboard读取，隔离提交前的旧读取响应；操作成功、失败及重新读取可见，不清空数量。
- 生成缺少平台幂等键，因此不自动重试写入；前端同步引用锁及本草进程内控制锁阻止并发提交。超时或异常回执明确表示未确认，提醒先核对平台，不能将其显示为成功。不同进程或不同客户端手动再次生成仍会新增批次。
- 保留现有40px操作栏、手机网格和底部数据读取时间；任务列表、报告、停止和导出仍待用户后续提供内容。

## 验证

- 新增8项后端测试覆盖鉴权、CSRF、严格数量边界、三种角色操作、请求路径与参数、网关及代理、回执确认、错误脱敏、超时不重试和并发拒绝。
- 全量后端命令`.venv/Scripts/python.exe -m unittest discover -s tests -v`：203项通过。
- 前端`pnpm typecheck`通过；最终源码在既有隔离副本以单线程、单工作进程`pnpm build`通过，未改正式构建配置。
- 本地开发页面以模拟接口在1440 / 836 / 320px核验：生成指定3批、开始、暂停、数量无效、提交中锁定、错误提示、重新读取不重复写入、恢复成功、关闭保留父标签及草稿。控件40px、无横向溢出、无浏览器运行错误。已查看桌面和手机截图。
- 真实平台通过同一后端路由新增1个匿名演示批次`batch_2c6655077f3a40b1`，处方总数由35增加到36；暂停回执及直接状态均为false，开始后均为true。最后恢复并确认原先的运行状态true。使用临时本地测试数据库和账号，没有新增正式账号或修改正式登录会话。
- 本地后端已重启加载接口，原模型预热完成，四个控制路由均已登记；8000健康接口、3000登录页与API代理正常。后续只读检查确认平台仍运行、处方36条；正式后端日志确认`GET /api/simulation/status`返回200，期间出现的连接失败已恢复。没有再次生成演示数据。
