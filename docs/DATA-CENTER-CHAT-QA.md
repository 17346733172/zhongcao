# 聊天关联数据中心验收

日期：2026-11-13。

## 行为

针对用户截图中的「我现在工作有几个锅？」，聊天在知识库检索前识别运行状态问题，直接使用数据中心已校验的同一仿真快照。按 `kind=pot` 和设备真实状态计数，区分煎药锅与其他工位；不调用 DeepSeek 猜测数量。

- 支持常见锅 / 设备总数、使用中、空闲、故障、停用及报警 / 统计概况问题。
- 「空闲的呢」「哪几台」等追问承接上一轮设备主题，每轮重新取状态，不使用旧回答中的数字。
- 标明数据中心来源与实际读取时间。缓存过期或更新失败时注明是上次记录，无法确认实时状态；没有有效快照时不给出虚构的 0 台。
- 数量回答的「使用中」按平台设备占用统计，不等同于所有设备都在加热或实际工厂产能。
- 「铁锅能不能煎药」「工作原理」「陈皮功效」仍走知识流程；运行数字不会进入药材模型上下文。聊天仅查询，不修复、启停或写入平台。
- 回答下的「查看数据中心」打开对应设备类型和状态，报警问题定位报警记录。打开的是数据中心当前记录，不锁定历史回答时的快照。
- 知识库加载失败或模型未配置时仍可查询运行数据；不将设备回答追加成药材原文摘录。

- 前端类型检查通过，33 项回归通过，新增覆盖数据中心结果不做药材提取、来源和快捷入口展示、运行历史仅传主题不传数字。
- 隔离复制当前前端源码和配置，复用已有依赖执行 `pnpm build --webpack` 通过，避免干扰实际开发服务缓存。
- 没有新增依赖、环境变量或平台控制接口；复用已修复连接生命周期的唯一后台读取任务。

## 浏览器真实数据

Headless Chrome 1440 / 390 / 320px，当前真实 Next.js 页面通过临时认证后端读取实际配置的平台。验收后端明确不配置 DeepSeek Key，证明运行问答没有云模型依赖；未发送药材资料到模型，也未修改真实账号或平台处方。

三种宽度均验证：

1. 输入用户原句，返回数据中心来源、时间和真实锅数量，未出现药材资料不足提示。
2. 点击「查看数据中心」，直接打开设备标签，设备类型为煎药锅、状态为使用中。
3. 继续问「空闲的呢」，承接煎药锅主题并打开空闲筛选。
4. 问「有哪些锅故障了」，按真实状态回答并打开故障筛选。
5. 桌面额外验证历史报警回答及全部报警筛选 / 区域定位。
6. 无整体横向溢出或页面错误，Escape 可关闭弹窗并继续提问。

验收时真实平台返回煎药锅总数 50 台、使用中 1 台、空闲 49 台、故障 0 台；这些数字随运行变化，不是硬编码。运行问答日志不含模型生成或检索阶段。

320px 另将知识库列表 / 基础文档加载失败设为浏览器本地测试场景，仍成功得到真实运行回答。只有资料加载错误是模拟，运行问答与数据中心响应均由实际平台数据构造，未使用业务数据替身。

本机后端已通过原独立启动入口重启加载聊天分流；前端开发服务已加载相关交互。实际 8000 OpenAPI 的 `ChatTurn.channel` 已包含 `knowledge / data_center`，确认运行进程加载新协议。登录页、后端健康和前端 API 代理均通过。
