# 工作区外层滚动修复验收

日期：2026-11-19。

用户截图显示聊天区域右侧同时出现两条竖向滚动条。既有样式已让 `.main-panel` 负责主内容滚动，但 `html / body` 仍允许溢出。隔离 Chrome 中连续三轮长回答不会撑高根页面；在 `body` 后附加一个 120px 高的模拟元素后，1000px 视口的文档高度变成 1120px，可复现外层网页与主栏同时滚动。

本轮未能通过桌面连接取得用户当前 Chrome 标签页的 DOM，因此仅确认上述可复现的布局缺口，不认定截图里的某个浮层或浏览器插件就是实际触发者。

## 修正

`frontend/src/app/page-scroll.css` 在存在 `.workspace` 时对 `html / body` 设置 `overflow: clip`，主栏仍用 `overflow-y: auto`。不通过隐藏主栏滚动条处理，不截断回答。选择 `clip` 是因为对比验证中，`hidden` 仍允许 `body.scrollTop` 被程序设置到 120；`clip` 保持为 0，避免外层被焦点或程序额外移动。工作区卸载后条件选择器自动失效，登录和账号页恢复自然滚动，无需额外的全局状态或事件。

## 验证

使用本机 Chrome 的隔离上下文和明确标识的模拟账号 / API 回应，没有读取实际浏览器凭据、调用模型或写入仿真平台。五种窗口全部通过：1830×900、1440×1000、390×844、320×844、1280×600。

- 两轮各 65 段长回答及图表完整可达，主内容竖向滚动容器只有 `.main-panel`；鼠标滚轮确实移动主栏，回答包装本身不滚动。
- 附加 120px 模拟元素后，根文档高度仍等于视口，`window.scrollY` 和 `body.scrollTop` 保持 0，无整体横向溢出；键盘聚焦输入框和切换按钮不会带动外层页面。
- 标题及输入区可见，输入区背景与留白保持；运行总览 / AI Agent 切换保留阅读位置和草稿。
- 引用弹窗可滚动、关闭并恢复主栏，打开期间背景滚动锁定；展开图表数据仍只有主栏竖向滚动。
- 跳转账号页和模拟未登录的登录页后，根页面溢出恢复；追加高内容时可正常滚动，验证没有全站锁死。
- 无 `pageerror`。`pnpm typecheck` 通过，真实本机前后端及 API 代理健康检查通过。
