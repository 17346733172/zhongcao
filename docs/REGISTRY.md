# 组件构建、校验和分发说明

状态：组件 registry 预留规范，尚未实现。最后更新：2026-10-26。

## 1. 是否需要 Registry

普通前端应用可以只维护内部组件，不需要 registry。只有需要跨项目复制、安装或分发组件时，才启动本规范的实现。

当前组件源码位于 frontend/src/components，仅供本应用内部使用。没有独立组件登记、分发地址或公共包，本文仍是后续分发规范。

## 2. 分发方式待决策

| 方式 | 适用目标 | 需要确定 |
| --- | --- | --- |
| 应用内部复用 | 组件只供本项目使用 | 内部导出和目录约定 |
| 源码分发 | 消费方复制或拉取源码后修改 | 文件清单、依赖、样式、路径转换 |
| 独立包分发 | 多项目通过依赖使用 | 包名、公开导出、版本和发布目标 |

先选方式再决定元数据格式与工具，不默认兼容某个第三方 registry 协议。

## 3. 建议登记内容

| 字段 | 用途 |
| --- | --- |
| 稳定标识与名称 | 定位组件，避免重名 |
| 描述与分类 | 用于搜索、导航和说明 |
| 版本 | 关联真实发布内容 |
| 源文件与入口 | 明确需要交付的文件和公开导出 |
| 依赖与环境 | 声明运行前提及相关组件 |
| 样式与资源 | 记录令牌、字体、图标和图片要求 |
| 示例与文档 | 支持预览和接入 |
| 许可 | 说明分发与使用条件 |

以上是字段设计建议，不是现有 schema。启用时再确定格式、必填项和兼容策略。

## 4. 构建流程

候选流程为：读取已确认登记数据 → 解析源码和资源 → 执行相应构建 → 生成与分发方式匹配的产物 → 校验 → 预发布验证。

构建产物应能追溯到源码版本，不包含密钥、本地绝对路径或无关演示资料。输出目录和命令在实现后补充到 [DEVELOPMENT.md](DEVELOPMENT.md)。

## 5. 校验要求

- 名称唯一，登记字段完整，文件路径存在且位于允许分发的范围。
- 依赖、公开入口和样式资源与实际源码一致。
- 示例使用当前接口，文档中的代码可按说明运行。
- 核心交互和键盘操作在实际消费场景可用。
- 分发产物能在干净环境中引入，不依赖开发者本机的隐藏配置。
- 版本与更新说明一致，破坏性变更有明确说明。

## 6. 发布与维护

确定目标和版本后再执行实际发布。发布后验证真实访问或安装结果，记录产物、来源版本和回退方式。

网站部署与组件分发是不同流程，网站上线不代表组件已经发布。站点托管见 [DEPLOYMENT.md](DEPLOYMENT.md)。
