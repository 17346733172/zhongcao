# 数据中心真实缓存与后台刷新验收

日期：2026-11-13。

本记录验证缓存可用性，并未解决实时更新链路。用户后续反馈仍有更新失败后，继续对照发现浏览器使用本机代理、后端固定直连；已补充显式代理配置，连续真实平台更新的最新验收见[连接修复验收](DATA-CENTER-PROXY-QA.md)。

## 问题与调整

首轮延长超时后，用户仍反馈概览长期停留在「正在读取平台数据」。继续分阶段测量：TCP / TLS 和收到响应头通常不到数秒，但完整仿真快照约 173 KB，响应体下载两次达到 35 秒的诊断截止时间仍未完成。轻量统计约 34 KB 也曾需要 9–12 秒，连接复用后仍可能间歇超时。因此单纯把页面等待延长到 75 秒不能解决空白首屏。

现行实现将本地展示与远程刷新分开：

- 登录后读快照状态，只返回已经校验的最近成功数据、实际读取时间、后台更新 / 过期状态及脱敏错误，不等待平台下载。
- 同一后端实例共用一个后台任务和 HTTP 连接；多次打开 / 刷新不重复启动平台请求。整轮更新限定 45 秒，取消未完成的异步网络读取，结束后等待 15 秒再尝试。
- 使用平台已有 `dashboard`、活跃状态的分页批次和完整分页报警。跳过数量为零的活跃状态，不在每轮下载已完成批次的全部历史工序。历史批次摘要由展开处方触发单独读取，失败可重试。
- 仅将通过响应模型验证的快照原子保存到 SQLite 旁的缓存文件。按连接地址校验来源，损坏或来源不同的缓存不用；缓存不保存密钥、原始处方或报告。
- 浏览器状态读取最多等待 5 秒；后台更新期间每秒读取本地状态，空闲时每 15 秒读取。没有缓存时不填入演示统计，5 秒后给出慢连接说明，标签与关闭仍可操作。
- 重复读取缓存不更新平台数据时间。连接失败时保留旧数据和原时间并明确提示，不将缓存当作实时结果。

轻量统计和活跃明细由同一轮的多个只读接口取得；平台运行期间，各请求的状态可能相差数秒，后续刷新会继续更新。远程网络故障仍可能持续，缓存改善页面可用性，不代表链路已经提速或恢复。

## 真实数据与浏览器验证

实际连接平台的一轮轻量刷新耗时 12.52 秒，取得 25 张处方、129 台设备并保存真实快照。后续本机后台也成功更新了缓存。浏览器验收使用该真实缓存的副本和临时 SQLite 账号，避免改动实际登录数据。

Headless Chrome 最终结果：

| 尺寸 | 打开到统计出现 | 离线时重新打开 | 快照状态请求最大耗时 |
| --- | ---: | ---: | ---: |
| 1440px | 1276 ms | 86 ms | 621 ms |
| 390px | 374 ms | 347 ms | 13 ms |
| 320px | 387 ms | 327 ms | 18 ms |

上述为本次本地开发环境的观测值，不是稳定性能承诺。

三种尺寸均核验真实统计、设备标签切换、离线后保留原读取时间、关闭 / 重新打开、无整体横向溢出和页面异常。320px 另核验无缓存慢连接说明及标签仍可操作，处方展开前不请求历史批次、展开后显示关联追溯码。

故障与慢连接为隔离后端 / 浏览器本地场景，不代表平台当时的真实故障；处方按需详情使用明确标为 `LOCAL-QA` 的本地数据，统计来自真实快照，未混称为真实业务联调。验收脚本首次退出时发现关闭页面后的未完成转发请求，已修正等待与清理；批次请求次数断言也按 React 开发 StrictMode 的挂载重放调整，最终完整脚本通过。

## 本机生效与限制

本草后端已通过原独立启动入口重启，新进程完成 Qwen / FAISS 预热（本次 75.56 秒）。8000 健康接口、3000 登录页和 API 代理均通过，真实页面的快照状态轮询持续返回 200。后台仍有网络超时日志，页面会保留最后成功数据并标明时间。

处方分页仍按操作读取平台；首次从未取得快照且网络持续不可达时，系统只能显示真实连接状态与重试说明。共享后台任务按后端进程合并；当前默认单进程部署，未实现跨多个服务进程的任务协调。
